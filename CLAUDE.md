# xcopilot — правила проекта

AI co-pilot для X: Telegram-бот учится голосу аккаунта, готовит посты и ответы, проверяет их кодом и судьёй, публикует только человек.

- ТЗ (источник правды): [docs/architecture-v3-plan.md](docs/architecture-v3-plan.md). Агентам давать только нужный раздел (например, «Этап 4» + «0.4 Модель данных»), не весь файл.
- Статус и очередь этапов: [docs/README.md](docs/README.md).

## Роли

- **Главный чат = оркестратор.** Планирует, выбирает модель и усилие, раздаёт задачи, проверяет, сливает ветки в `main`, пушит и только он деплоит. Сам код не пишет, кроме мелких правок.
- **Одна задача = новая сессия (context "fresh") + своя ветка.** Этапы ТЗ — ветки `stage/NN-имя`, мелочи — `fix/…`, `docs/…`.
- Исполнитель доводит ветку до зелёных тестов, **не сливает в main и не деплоит**, сообщает главному чату: «готово, ветка X».
- Готовую сессию оркестратор сам проверяет, сливает, переносит итоги в `docs/` и память, архивирует.
- **Главный чат тоже перезапускается.** Длинный контекст дорог: когда главный чат разросся (примерно после 2–3 этапов), он обновляет `docs/README.md` и память и предлагает новый главный чат.

## Оркестратор ведёт всё сам

Владелец не заходит в сессии-исполнители. Оркестратор сам утверждает их планы, отвечает на технические вопросы, сливает и запускает следующие согласованные задачи. Владельцу в главный чат — только то, что может решить только он (деньги, ключи, аккаунты, бизнес-правила, реальные данные), пачкой. В брифах: «план и вопросы — главному чату через SendMessage; не жди ответа владельца».

## Порядок работы

1. Задача больше мелкой правки → короткий план, обсуждаем с владельцем, стартуем только после «да».
2. Новая сессия с планом как брифом, модель и усилие — по таблице ниже. Одной строкой: что выбрал и почему.
3. В брифе: раздел ТЗ, файлы/область, что значит «готово», «не деплой и не сливай; по готовности сообщи ветку главному чату».
4. Оркестратор проверяет дифф и тесты, сливает в `main`, пушит.
5. Перед передачей — `docs/` и память содержат всё нужное новой сессии.

## TDD (из ТЗ, раздел 1.0)

Первые коммиты этапа — только тесты из «Тесты (до кода)» + пустые заглушки, тег `stage-NN-red`. Исходные тесты не меняются; неверный тест — отдельный коммит `test-fix:` с объяснением. Этап закрыт, когда зелёные все тесты этапа и выполнен общий критерий готовности.

## Выбор модели и усилия

| Задача | Модель | Усилие |
|---|---|---|
| Проверки статуса, чтение и пересказ, простые правки файлов | Haiku (`claude-haiku-5-5`) | low |
| Понятный код по готовому плану, небольшой этап (S/M) с тестами, документация | Sonnet (`claude-sonnet-5-5`) | medium |
| Большие этапы ядра (L), рискованные деплои, известные интеграции (X API, Anthropic) | Opus (по умолчанию) | medium |
| Архитектура, сложные баги, производительность, новые интеграции (Jev), оценка качества текста | Opus (по умолчанию) | high |

Сомневаешься — бери дешевле; сессия может попросить повысить.

## Исполнитель DeepSeek: `scripts/ds.py`

DeepSeek — «руки» для простых шагов. **Чёткая задача — чёткий результат, никакой самодеятельности.** Подробно: [docs/deepseek/README.md](docs/deepseek/README.md).

- Задание — md-файл в `docs/tasks/`: `## Файлы`, `## Новые`, `## Контекст`, `## Задача` (точные шаги, имена функций, сигнатуры, что вернуть), `## Коммит`.
- Запуск в ветке задачи: `python3 scripts/ds.py docs/tasks/<задание>.md [--model …] [--thinking]`. Модель и режим выбирает тот, кто ставит задание (таблица в docs/deepseek).
- DeepSeek получает только перечисленные файлы одним запросом и возвращает их целиком; лишнее скрипт отбрасывает; затем ruff, mypy, pytest, до 2 кругов починки, коммит.
- Один шаг = 1–3 файла. Результат всегда проверяет Claude: `git diff`, тесты. Не нравится — новое точное задание на доработку.
- DeepSeek не трогает: деньги и бюджеты, схему БД и миграции, безопасность и секреты, промпты судьи/писателя, тесты этапа (их пишет Claude до кода).

## Git

- Репозиторий: `git@github-xcopilot:mchiretsmaxmax-maker/xcopilot.git` (приватный; deploy-ключ `~/.ssh/id_ed25519_xcopilot`, алиас `github-xcopilot` в `~/.ssh/config`).
- `main` — ветка оркестратора, всё попадает в неё только через главный чат.
- Рабочие папки веток — постоянные слоты `.worktrees/slot1..slot3` (приложение спрашивает доверие к каждому новому пути один раз; слот не меняет путь, поэтому вопрос не повторяется): `scripts/slot.sh <N> <ветка>`, сессия стартует с `cwd` слота. После слияния ветки слот свободен. `.worktrees/02-db-core` — разовая, удалить после этапа 2.
- Ветки, рабочие папки, запуск и архив сессий оркестратор делает сам, владельца не спрашивает (решение владельца 13.11.2026).
- Папка проекта `~/Projects/xcopilot` — вне iCloud, специально.
