## Работа с владельцем

Основной чат Codex ведёт задачу целиком: планирует, реализует, проверяет и докладывает результат. Технические решения принимает сам. Вопросы про деньги, доступы, продуктовые решения и реальные данные собирает в один запрос. Пуш и деплой выполняет по запросу владельца.

1. Для изменений больше мелкой правки согласуй короткий план. Явная просьба выполнить уже описанный объём даёт старт.
2. Работай в отдельной ветке от актуального `main`. Для этапов используй `stage/NN-имя`, для остального — `feat/…`, `fix/…`, `docs/…`.
3. Для реализации сформулируй критерий готовности и проверь внешний сценарий, дифф и тесты.
4. Если владелец просит делегировать, исполнитель работает в отдельном worktree и передаёт ветку основному чату. Основной чат проверяет результат, принимает решение о слиянии и выполняет согласованные внешние действия.
5. Перед передачей обнови статус и существенные решения в `docs/`. В новом чате начни с этих документов и истории Git.

## TDD (из ТЗ, раздел 1.0)

Первые коммиты этапа — только тесты из «Тесты (до кода)» + пустые заглушки, тег `stage-NN-red`. Исходные тесты не меняются; неверный тест — отдельный коммит `test-fix:` с объяснением. Этап закрыт, когда зелёные все тесты этапа и выполнен общий критерий готовности.

## Модель и усилие Codex

| Задача | Модель | Усилие |
|---|---|---|
| Статус, чтение, небольшая правка | GPT‑6.2 Sol | `low` |
| Обычная разработка, тесты, документация | GPT‑6.2 Sol | `medium` |
| Архитектура, сложные баги, миграции и интеграции | GPT‑6.2 Astra | `high` |

Разработка по умолчанию настроена в `.codex/config.toml`. Если модель недоступна в аккаунте, выбери доступную модель Codex соответствующего класса. Для писателя приложения действует отдельный профиль в `config/models.toml` и `CODEX_CLI_EFFORT`.

## Исполнитель DeepSeek: `scripts/ds.py`

DeepSeek — «руки» для простых шагов. **Чёткая задача — чёткий результат, никакой самодеятельности.** Подробно: [docs/deepseek/README.md](docs/deepseek/README.md).

- Задание — md-файл в `docs/tasks/`: `## Файлы`, `## Новые`, `## Контекст`, `## Задача` (точные шаги, имена функций, сигнатуры, что вернуть), `## Коммит`.
- Запуск в ветке задачи: `python3 scripts/ds.py docs/tasks/<задание>.md [--model …] [--thinking]`. Модель и режим выбирает тот, кто ставит задание (таблица в docs/deepseek).
- DeepSeek получает только перечисленные файлы одним запросом и возвращает их целиком; лишнее скрипт отбрасывает; затем ruff, mypy, pytest, до 2 кругов починки, коммит.
- Один шаг = 1–3 файла. Результат всегда проверяет Codex: `git diff`, тесты. Не нравится — новое точное задание на доработку.
- DeepSeek не трогает: деньги и бюджеты, схему БД и миграции, безопасность и секреты, промпты судьи/писателя, тесты этапа (их пишет Codex до кода).
