# ADR 0025 — Карточки и публикация (этап 12)

Статус: принято (15.11.2026).

## Решения

1. **Модули.** `review/cards.py` (`CardDraft`, `CardView`, `render_card`, `split_text`, `WhyItem`, `render_why`), `review/callbacks.py` (`CardCb`, `card_cb`, `short_id`/`from_short`), `review/decisions.py` (`Decisions`, `DecisionResult`, `CardExpired`, `Relinter`, `edit_distance`), `review/publish.py` (`publish_view`, `Publisher.view/confirm_published`, `record_publication`, `LinkError`/`ForeignLinkError`), `review/matcher.py` (`PublicationMatcher.match_publications`, `similarity`, `Match`), `review/presenter.py` (`CardPresenter`: показ, навигация, срок, очередь, «Почему так»), `review/expiry.py`, `review/jobs.py`, `review/kit.py` (`ReviewKit`, `build_review`), `review/settings.py` (`ReviewSettings`). Бот: `bot/routers/cards.py`, `bot/routers/queue.py`, состояния `CardFlow` (правка, своя подсказка, ссылка). Запросы — `db/repos/review.py` (`ReviewCardsRepo`, `ReviewQueries`).
   - Отступление от ТЗ в сигнатурах: функции ТЗ (`approve(draft_id, user_id)` и т. п.) — методы сервисов с первым аргументом `account_id` (тенант; все репозитории скоупятся по аккаунту). `match_publications(account_id, own_posts)` и `confirm_published(draft_id, url=None)` — методы `PublicationMatcher`/`Publisher`.
2. **Миграция 0009.** `review_cards` (запуск × чат: `message_id`, `variant_no`, `state` queued/shown/expired, `shown_at`) и `reviews.comment`. Без таблицы нельзя редактировать одно сообщение при навигации, снимать кнопки по сроку, считать дневной предел и вести /queue. Номер 0008 оставлен этапу 9C; `down_revision = "0007"` — если 9C добавит 0008, при слиянии перевести на 0008.
3. **Карточка.** HTML (parse_mode явно), текст черновика и тема экранируются. Шапка «📝 Вариант N/M · формат · длина/280» (тред — «N частей»), строка «🧪 Проверяю приём: …» (guidance испытуемого знания из `context_pack.probation`, только у варианта с `probation_item_id`), «Тема: …» (тема из `topics` или `task.topic`), разделители, строка ворот `quality.render.gate_line` по решению, восстановленному из `drafts.lint_report.gate` (`quality.loop.restore_decision`). Карточка длиннее 4096 знаков: текст уходит отдельными сообщениями до карточки (`CardView.before`, режем по исходному тексту — абзацы → строки → слова → символы, сущности `&amp;` не рвутся), сообщение с кнопками короткое.
4. **Callback-данные.** `c1:<черновик>:<действие>:<аргумент>`: `c1` — версия схемы; ID черновика — 22 знака base64url; аргумент — номер варианта, код причины/подсказки или ID поста X (до 20 цифр). Худший случай ≤ 64 байт (тест). Проверка доступа: черновик ищется в аккаунте нажавшего; нет — «не из твоего аккаунта» (незнакомых отсекает `AuthMiddleware`).
5. **Показ после ворот.** `writer.generate` (воркер) ставит `quality.gate` с ключом идемпотентности по черновикам; разбор хвоста и предупреждения писателя приходят сразу, карточки — нет. Обработчик `quality.gate` после решений вызывает `presenter.show_for_drafts`. Без очереди (`gate_queue=None`, прямые вызовы этапа 10) — старый путь с простыми карточками. Карточка показывается по финальным ревизиям в статусах `judged`/`needs_owner`; статус `shown`, строка `review_cards` и `card.shown` пишутся только после успешного `sendMessage` (ошибка Telegram — ничего не меняется). Повтор задачи ворот не шлёт карточку второй раз.
6. **Дневной предел.** `daily_card_limit` (10 запусков в локальный день аккаунта): сверх — `review_cards.state = queued`, черновики остаются `judged`. /queue показывает список и кнопку «Показать» (самая старая, мимо предела).
7. **Решения.** Строка черновика блокируется (`SELECT … FOR UPDATE`) — повторное нажатие получает `repeated` и ничего не пишет. Одобрить/отклонить — только из `shown` (отклонить ещё из `needs_owner`), править — из `shown` или `edited` (повторная правка — новая пара «до/после», событие `review.edited` одно на черновик). `reviews.created_at` и время событий — из часов приложения (окна сверки считаются по ним). Правка: нормированная дистанция Левенштейна (rapidfuzz) к предыдущему тексту, повторный линтер `QualityGate.relint` (контекст ворот, без записи) — ошибки показываются предупреждениями, блок публикации всё равно приходит. Тред: части исправленного текста — по пустым строкам. «Ещё вариант»: подсказки Короче/Жёстче/Другой заход или свой текст → новая `writer.generate` по задаче запуска (`context_pack.task`, цель, тема; хвост тренда — по ссылке, без подсказки) с ключом `regen:<review>`. Отказ — только с причиной из пяти кодов (`not_my_voice`, `off_topic`, `sounds_ai`, `wrong_fact`, `other`); `comment` есть в API, в боте не спрашивается.
8. **Совместимость (v3.1).** Каждое решение в той же транзакции вызывает `brain.evidence.record_from_review` (9A, сигнатуры не менялись): одобрен без правок +1.0, сильно переписан (дистанция ≥ `heavy_rewrite_distance` 0.5) −0.5, «не мой голос»/«звучит как AI» −1.5, прочее — ничего; только для применённых знаний финальной ревизии (`applied IS NOT FALSE`). Одно доказательство на знание × черновик (уникальный индекс 9A). Пересчёт весов — ночью (`brain.nightly`).
9. **Срок.** Карточка старше 48 часов от показа: кнопки карточки отвечают «устарела», с сообщения снимаются кнопки, карточка и нерешённые варианты → `expired` (отдельной транзакцией до ответа). Задача `cards.expire` делает то же без нажатий. Решённые варианты не устаревают: блок публикации и ссылка работают и позже.
10. **Публикация.** Бот в X не пишет. `publish_view`: пост ≤ 280 взвешенных знаков — Intent; ответ — Intent с `in_reply_to`; цитата — адрес поста в конце текста; длиннее 280 и треды — режим копирования (тред — блок на часть, «📋 Скопировать» шлёт блоки в `<pre>`). «✔️ Опубликовал» → «Пришли ссылку или [Найди сам]». Ссылка: чужой хэндл в адресе или у поста — отказ (свой — без учёта регистра); итоговый текст и время — из самого поста (`XClient.get_post`, только чтение; X недоступен — текст черновика); адрес хранится с хэндлом аккаунта. «Найди сам» ставит `publications.match` сразу.
11. **Автосверка.** `publications.match`: свои посты (`get_own_posts`, 50 свежих; X выключен — пустая лента) против одобренных/исправленных черновиков; пост учитывается, если вышел в окне [решение − 10 мин, решение + 48 ч]; rapidfuzz ratio без регистра и лишних пробелов; ≥ 0.85 — публикация `auto` (`publication.matched` + `publication.confirmed`), 0.6–0.85 — вопрос владельцу [Да, это он]/[Нет] (да — `manual`), после окна без совпадения — `unconfirmed`. Один пост — одному черновику (лучшее сходство). Запуски: через 3 и 12 часов после решения, сразу после окна (+49 ч), ежедневно в 21:00 (`DEFAULT_SCHEDULES`) и по кнопке.
12. **Очередь и сборка.** `KNOWN_KINDS` + `build_registry`: `cards.expire`, `publications.match`; `JobDeps.review`, `BotDeps.review` (`ReviewKit`) собираются в `app.build_app` (`relinter` = те же ворота). `DEFAULT_SCHEDULES`: `cards.expire` 04:00, `publications.match` 21:00.

## Не сделано / дальше
- Критерий «на настоящем аккаунте» (тема → три варианта → правка → ссылка → подтверждение; автосверка без ссылки) закрыт тестом полного прохода на стенде (`tests/integration/bot/test_cards_e2e.py`); живая проверка ждёт токенов бота и X.
- Вопрос о неоднозначном совпадении может повториться при следующих сверках, пока владелец не ответит (отметки «уже спрашивали» нет).
- Комментарий к отказу «Другое» в боте не спрашивается (поле и API есть).
- Доставка (аудит D, AUD-004): `send_with_retry` повторяет отправку, недошедшая карточка роняет `quality.gate` на повтор; известное ограничение — при сбое посреди длинной карточки начальные части текста (`CardView.before`) могут прийти дважды.
