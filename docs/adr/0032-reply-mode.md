# ADR 0032 — Режим «💬 Ответы»

Статус: принято (17.11.2026). Ветка `feat/reply-mode`. Миграции нет.

## Проблема

Ответ на чужой пост делался через общий «✍️ Пост → Ответ → цель → о чём сказать»: четыре шага и большая карточка с ◀ ▶ и одобрением. Владельцу нужно проще: прислал ссылку → получил 3 ответа → нажал «Ответить в X».

## Решение

1. Кнопка «💬 Ответы» в постоянном меню → FSM `ReplyFlow.link` (`bot/routers/replies.py`, роутер стоит сразу после `start`).
2. Ссылка на пост читается без ключа X через `BotDeps.post_reader` — тот же `PostFetcher`, что в `XService` (`PublicPostReader` или `OEmbedReader` по `X_PUBLIC_READ`, ADR 0031). Бюджет X и API не трогаются. Свой пост допустим.
3. Генерация — обычный конвейер: `writer.generate` (формат `reply`, `TargetPost` с текстом, адресом и автором) → `quality.gate` → показ. Нового вызова модели нет.
4. Как показывать варианты, передаёт поле `view` в payload: `{"kind": "reply", "post_id": …}` идёт из `writer.generate` в `quality.gate`, обработчик ворот передаёт его в `CardPresenter.show_for_drafts`. При `kind=reply` вызывается `show_reply`: каждый вариант отдельным сообщением (`render_reply_variant`: текст, строка проверки ворот, перевод при нужде) и в конце «🔁 Ещё варианты» / «✖️ Выйти из режима». Старые payload без `view` не меняются.
5. Кнопки варианта: «↩️ Ответить в X» — URL `build_reply_intent(text, post_id)` (нет, если текст > 280 взвешенных знаков); «📋 Скопировать» — `CopyTextButton` (нет, если текст > 256 знаков: это предел Telegram; тогда текст в сообщении идёт блоком `<code>` и копируется тапом).
6. Чтение не удалось (`XError`, читатель выключен) → «пришли текст поста», состояние `ReplyFlow.manual`: следующий текст становится целевым постом, id из ссылки сохраняется для intent.
7. Одна активная генерация режима на аккаунт: пока есть `writer.generate` или `quality.gate` с `view.kind = reply` в статусе queued/running (`JobQueue.has_active_view`), новая ссылка, ручной текст и «🔁 Ещё варианты» получают «ещё готовлю прошлые варианты». Обычные генерации не мешают.
8. Режим держится между ссылками; выход — «✖️ Выйти», /cancel, любая другая кнопка постоянного меню (состояние снимается, кнопка срабатывает как обычно через `SkipHandler`). Команды в режиме работают как обычно.

## Последствия

- Дневной предел карточек к режиму не применяется (владелец сам прислал ссылку, а очередь ограничена п. 7); строк `review_cards` нет, черновики сразу `shown`, событие `card.shown` пишется как обычно.
- URL-кнопка не присылает боту колбэк, поэтому выбранный вариант не отмечается. Автосверка публикаций (`publications.match`) смотрит только одобренные черновики, так что ответы из режима в неё не попадают. Если понадобится учёт, нужна отдельная кнопка «✅ Выбрал» → `Decisions.approve`. Сейчас её нет: новый механизм не вводили.
- Черновики режима не истекают через `cards.expire` (нет строк карточек); на работу бота это не влияет.
