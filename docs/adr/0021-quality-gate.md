# ADR 0021 — Ворота качества (этап 11)

Статус: принято (15.11.2026).

## Решения

1. **Модули.** `quality/lint/engine.py` (`Rule`/`FixableRule` Protocol, `Finding`, `LintDraft`, `LintContext`, `LintReport`, `Linter`), `quality/lint/rules/*` (14 правил), `quality/lint/numbers.py`, `quality/lint/text.py` (ссылки, @, #, $тикеры, эмодзи, свёртка ё/регистра), `quality/judge.py`, `quality/policy.py`, `quality/instructions.py`, `quality/loop.py` (`QualityGate`, `GatewayRewriter`), `quality/attribution.py` (`mark_applied`), `quality/knowledge.py` (`ClassCRules`), `quality/brain_detector.py`, `quality/settings.py`, `quality/render.py`, `quality/jobs.py`. Запросы — `db/repos/quality.py` (`QualityRepo`). Миграции нет: `drafts.lint_report/judge_verdict/parent_draft_id`, `knowledge_applications.applied*` уже были; пороги аккаунта — `accounts.settings["thresholds"]`.
2. **Линтер.** Правило = id + уровень + `check`; исправляемые (`casing`, `hashtags`) сначала правят текст той же ревизии (находка с `autofixed=true`, не ошибка). Упавшее правило → предупреждение `internal`, линтер не падает (property-тест hypothesis). Уровни: всё `error`, кроме тройных перечислений в `ai_patterns` и `knowledge_c` (`warn`).
   - `length` — `x.intents.weighted_len`; пост — до `hard_rules.max_len`, ответ/цитата — до min(max_len, 280); тред — правилом `thread_structure` (3–8 частей по 280).
   - `ai_patterns` — регулярки RU/EN: «не X, а Y», «не только…, но и», «it's not X, it's Y», штампы-зачины; ≥ 3 тире — ошибка.
   - `number_grounding` — 1.2M = 1,200,000 = 1.2 млн = 1,2 млн; `%` сверяется только с `%`; источники — факты пакета и ввод пользователя (тема, подсказка, текст целевого поста); не проверяются нумерация списков, метки треда `1/3`, годы 1990–2100. Маленькие числа без единиц **проверяются** (выдуманное «в 3 раза» — тоже цифра).
   - `mention_safety` — @ только из ввода/фактов. `language` — доля латиницы/кириллицы (≥ 20 букв, без ссылок/@/#/$).
   - `duplicate_of_recent` — свои материалы (stance own) за 60 дней, rapidfuzz ≥ 0.85.
   - `foreign_similarity` (v3.1) — чужие материалы (stance ≠ own, не убраны): сходство rapidfuzz > 0.6 или общая последовательность от 8 слов (слова после свёртки регистра и ё). Кандидаты — `QualityRepo.foreign_candidates`: pg_trgm в обе стороны (`%`, `<%`) по `documents`, до 30 штук; точная проверка — в правиле. Индекса триграмм по `documents` нет (есть по `chunks`) — при росте базы нужен индекс (миграция через главный чат).
   - `banned_phrases` — паспорт + глобальные `config/banned_phrases.toml`.
   - `knowledge_c` (v3.1) — рабочие знания класса C аккаунта и общего аккаунта (`DbClassCRules`): фразы в «…»/“…”/"…" из утверждения (шаблоны с X/Y/… пропускаются) → предупреждение. Знания без кавычек — только подсказка писателю.
3. **Судья ворот №2.** Один вызов `decide` на 7 вопросов (`QUESTIONS_GATE2`: voice_match 0–3, ai_smell 0–3, hook 0–2, on_topic/grounded/risky — да/нет, main_issue — выбор из 8). Состояние: тема, формат, краткий паспорт (без hard_rules/anti_examples), жёсткие правила, 3 примера автора, факты; черновик — `wrap_untrusted(..., "draft")` в конце. Ответ → `JudgeVerdict` (нет ответа или не тот тип → `JudgeParseError`). Порт — `JudgePort` (LLMGateway подходит как есть: DeepSeek сейчас, Jev — по ADR 0011). Стоимость: один короткий вызов на ревизию (~1.5–2k токенов входа DeepSeek flash — ниже $0.002 на черновик при ≤ 3 ревизиях, проверить по `llm_calls` после ночного eval).
4. **Политика.** Порядок: ошибки линтера → `rewrite` (судья не вызывается); нет вердикта → `pass` + `lint_only`; `risky > 0.3` → `needs_owner` + `risky` (не переписываем: решает человек); уверенность шкалы < 0.6 или да/нет в 0.4–0.6 → `needs_owner` + `judge_unsure`; иначе пороги (`voice_match ≥ 2.0`, `ai_smell ≥ 2.0`, `on_topic ≥ 0.7`, `grounded ≥ 0.7`) → `rewrite` с кодами `voice/ai_phrases/off_topic/unsupported_claim` (+ `main_issue`, если другое); резервный судья → `fallback_judge`. Пороги — `config/thresholds.toml [gate]`, аккаунт переопределяет известные ключи.
5. **Петля.** `QualityGate.run_gate(account_id, draft_id)`: линтер → (ошибка: переписать) → судья → решение; ≤ `max_rewrites` (2) переписываний, затем `needs_owner` + `max_rewrites`. Переписывание — `writer.rewrite.v1` (роль writer) через `Rewriter` (`GatewayRewriter`); новая ревизия `add_revision` (`parent_draft_id`), старая → `expired`. Писатель недоступен/ответ битый → `needs_owner` + `writer_unavailable`. Судья недоступен / бюджет / битый ответ → режим «только линтер». Статусы: pass → `linted` → `judged`; иначе `needs_owner`. LLM вне транзакций.
6. **Отчёты и идемпотентность.** `drafts.lint_report` = `{format (этап 10), findings, autofixed, gate}`; `gate` — решение без вложенных отчётов. `drafts.judge_verdict` = `JudgeVerdict`. Повторный `run_gate` по любой ревизии идёт к последней (`child_revision`) и, если там есть `gate`, возвращает его без вызовов и событий; прерванная петля продолжается с последней ревизии.
7. **События.** Новые (в конце `metrics/events.py`): `draft.gate_decided {outcome, revision, rewrites, flags}`, `knowledge.applied_marked {checked, applied}`. Используются: `draft.lint_failed {rule}` (по правилу-ошибке на ревизию), `draft.judged {verdict: pass|fail, score: voice_match}`, `draft.rewritten {revision, reason}`.
8. **Применённые знания (v3.1).** `mark_applied` на финальной ревизии: строки `knowledge_applications` ревизии 1 копируются на финальную (если их там нет), детектор ставит `applied/applied_score/checked_by/checked_at`; ревизия 1 остаётся `NULL`. Детектор — `AppliedDetector`: `NoDetector` по умолчанию, `BrainRubricDetector` — рубрики знаний 9A через `brain.detectors.eval_rubrics` (≥ rubric_present — да, ≤ rubric_absent — нет, между — не отмечается). **Feature-детекторы — заглушка**: смотрят на поля разбора материала, а разбора черновика нет; доделать, когда появится разбор черновика.
9. **Строка карточки.** `render.gate_line(decision)`: «Проверка: линтер ✅ · судья ✅ голос 2.6/3, AI 2.8/3», «⚠️ Судья не уверен: …», «… · Резервный судья», «Проверка: линтер ✅ · Проверен только правилами».
10. **Очередь.** `quality.gate` (`gate_payload(draft_ids)`, `gate_idempotency_key`), `handle_quality_gate`, `process_gate_job` (ошибка → `fail`). Воркера нет, как у писателя.
11. **Писатель.** Одна строка в `writer/drafts.py`: `context_pack.target_text` (текст целевого поста — ввод для `number_grounding`/`mention_safety`).
