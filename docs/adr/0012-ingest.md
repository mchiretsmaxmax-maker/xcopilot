# ADR-0012: Ингест (этап 7)

Статус: принято (этап 7, 13.11.2026).

## Контекст
Всё, что владелец присылает боту (текст, ссылки на посты, @аккаунт, файл), должно стать
очищенными кусками с тегами и векторами, без дублей; повторная отправка — без новых строк.
Таблицы `sources / documents / chunks / embeddings / embedding_models` есть с этапа 2.

## Решения
1. **Без миграции: статусы схемы.** ТЗ: `pending → parsed → embedded → ready | failed`. Схема:
   `new / parsed / indexed / failed / excluded`. Соответствие: `pending = new`; `embedded` и
   `ready` = `indexed` — куски, теги и векторы пишутся одной транзакцией, промежуточного
   состояния «векторы есть, тегов нет» не бывает. `excluded` — дубль или недоступно по режиму X
   (причина в `meta.reason`).
2. **Два шага, каждый — своя транзакция.** `new → parsed`: извлечь текст (X, файл), очистить,
   вычистить PII, записать `documents`. `parsed → indexed`: нарезка, близкий дедуп, теги,
   векторы. Теги и векторы считаются вне транзакции; запись — под `SELECT … FOR UPDATE` с
   повторной проверкой статуса. Сбой посередине оставляет прежний статус, повтор задачи
   доделывает работу; завершённый источник не меняется (идемпотентность).
3. **Задача.** `ingest.process`, payload `{"source_id"}`, ключ идемпотентности `ingest:<id>` —
   как ставит онбординг этапа 5. Ошибки входа (скан без текста, битый файл, нет поста) →
   `failed` + сообщение владельцу + событие `source.failed`, задача завершается без повторов.
   Временные сбои (X, эмбеддер) пробрасываются — очередь повторит.
4. **Дедуп.** Точный — `sources.content_hash` (уникален в аккаунте): текст — sha256 от
   `normalize(text)`, ссылка — `x-post:<id>`, хэндл — `x-handle:<имя>`, файл — sha256 байтов.
   Близкий — `pg_trgm similarity > 0.9` по `chunks.text` (индекс `ix_chunks_text_trgm`) против
   кусков других источников: кусок не вставляется; если новых кусков нет — источник `excluded`,
   `meta.duplicate_of` (источник) и `meta.near_duplicate_of` (кусок).
5. **Файлы между приёмом и обработкой** — `BlobStore` (`FsBlobStore` в `settings.ingest_dir` =
   `DATA_DIR/ingest`, по умолчанию `data/ingest`, папка в .gitignore; сборка —
   `ingest.factory.build_blob_store`; в тестах `MemoryBlobStore`), ключ — id источника;
   удаляются сразу после разбора — и при успехе, и при `failed`.
6. **PII** вычищается только у видов `file` и `chat` (и в `documents.text`, и в `text_clean`):
   e-mail, телефоны с `+код`/ведущей 8, номера карт с проверкой Луна. Свои и чужие посты не
   трогаются — хэндлы, тикеры и числа остаются.
7. **Нарезка.** Пост (own_post / liked_sample / competitor_post) — один кусок. Остальное —
   куски до 400 «токенов» (слово или знак препинания — без токенизатора модели) с перекрытием
   50, резка по концу абзаца, иначе фразы. Куски — срезы исходника, текст восстанавливается
   без потерь (property-тест). Текст из сообщения до 25 000 знаков (длинный пост X) — пост,
   длиннее — `note`. Несколько постов в одном сообщении разделяются строкой `---`.
8. **Теги** — промпт `ingest.tag`, роль `cheap`, пачки по 16, каждый кусок через
   `wrap_untrusted`. Схема `Tags` (material, topics ≤ 5, format, lang из двух букв); в
   `chunks.tags` — `material:… / format:… / topic:…`, язык — в `chunks.lang`. Сбой модели или
   бюджета → пустые теги, источник всё равно `indexed` (событие `llm.failed` пишет шлюз).
9. **Эмбеддинги** — `Embedder` (Protocol, синхронный, вызывается через `asyncio.to_thread`),
   пачки по 32; перед записью имя и размерность сверяются с активной моделью реестра
   (`paraphrase-multilingual-MiniLM-L12-v2`, 384), расхождение — `ConfigError`. Важно: у модели
   окно 128 токенов, длинный кусок кодируется по началу — для поиска по файлам это приемлемо.
10. **«Это что?»** Для партий текста и ссылок вид источника = догадка тегировщика (большинство
    `material`), итог партии приходит одним сообщением с кнопками, догадка отмечена ✓.
    Итог отправляет последний завершившийся источник партии (`meta.batch`, блокировка строк,
    флаг `meta.summary_sent`). Источники онбординга без партии итога не шлют.
11. **Чужой @аккаунт** вне `paid` — источник не создаётся, предложение «Пришлю текстом» /
    «Включить платное чтение» (`xc:paid` из `x_connect`). В `paid` — источник
    `competitor_post`, но у `XClient` нет ленты чужого аккаунта: источник `excluded`
    (`reason=radar`), посты конкурентов соберёт радар.
12. **Без сырого текста вне documents/chunks.** В `sources.meta`, логах и событиях — только id,
    счётчики, причины и имя файла; тексты с персональными данными туда не пишутся.
13. **События:** `ingest.accepted {input, sources, duplicates}`, `source.ingested {source_id,
    kind, chunks, duplicates}`, `source.failed {source_id, reason}`; действия в боте —
    `user.action` (`ingest.accept`, `ingest.kind`, `ingest.send_text`).

## Последствия
- Воркера ещё нет: `jobs.handlers.handle_ingest_process(job, service=…)` подключить при сборке
  воркера; сервис собирается из шлюза (`Tagger(gateway)`), `FastEmbedder()`, `FsBlobStore`,
  `Notifier(bot, uow_factory)` и фабрики `XClient` по аккаунту. В боте — `BotDeps.ingest`.
- Тест с настоящим fastembed помечен `slow` и исключён по умолчанию (модель качается из сети).
