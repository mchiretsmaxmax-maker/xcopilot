# ADR-0018: Разбор материалов (этап 7A)

Статус: принято (этап 7A, 15.11.2026). Опирается на [ADR-0015](0015-brain-db.md) (схема) и
[ADR-0017](0017-ingest-v31.md) (ингест v3.1).

## Контекст
ТЗ v3.1 «Мозг», этап 7A: каждый принятый материал получает признаки, разбор по словарям,
сигнал и исход, карточку в боте; своя история импортируется с исходами. Таблицы
(`taxonomy_terms`, `material_analyses`, `material_signals`, `material_outcomes`) и 70 стартовых
ключей словарей уже в main (миграции 0004/0005). Миграции этап не добавляет.

## Решения
1. **Версия таксономии без новой колонки.** Версия аккаунта = `max(since_version)` действующих
   значений (global + свои). Подтверждение предложения (`accept_term`) ставит значению
   `since_version = текущая + 1`, `status = active`, `created_by = owner`. Своё значение с тем же
   ключом перекрывает общее.
2. **Определения словарей — `config/taxonomy.toml`, черновик исполнителя, не из ТЗ** (ТЗ даёт
   только ключи); владелец может править. `load_seed` идемпотентен: вставляет только
   недостающие ключи, дописывает пустые определения и названия-заглушки (= ключ); версию не
   меняет. Вызывается один раз на процесс из `Analyzer`.
3. **Разбор** (`brain/analyze.py`, промпт `brain.analyze_material.v1` — текст приложения E):
   только `SourcesRepo.is_ready_for_analysis` (предикат `ready_for_analysis()`); материал и
   родитель — `wrap_untrusted`; словари первым блоком user-части; признаки кода — `<features>`.
   После схемы — `verify_quotes`; ключ вне действующего словаря → ближайший (difflib, без
   новой зависимости) и предложение `proposed / model`. `format` берётся из `sources.kind`.
   Ответ не по схеме дважды → `analysis_status = failed`. Модель и `llm_call_id` — из журнала.
4. **Переразбор**: материалы, чей текущий разбор сделан другим `analyzer_version` или меньшей
   версией таксономии; новая строка `is_current`, старая остаётся. Потолок — расход цели
   `brain.reanalyze` за сутки UTC, `config/brain.toml [analysis] reanalyze_daily_limit_usd`
   (0.10). `config/brain.toml` создан целиком по разделу 2.4 — остальное читает 9A.
5. **Сигналы**: `owner_pick` по умолчанию — только `stance = inspiration` (решение главного
   чата: конкурент и антипример — не «нравится»), один раз и только без других сигналов.
   `parse_numbers`: подписанные числа по меткам (views/likes/…, рус.), неподписанные — по
   порядку просмотры, лайки, ответы, репосты, закладки; `k/K/тыс/млн/m/b`, «1,2» — десятичная,
   «1,200» без множителя — тысячи.
6. **Исходы** (`config/outcomes.toml`, пороги раздела 1.3, нижняя граница включительно):
   `owner_label` → все цели = оценка; `owner_pick` → unknown; нет просмотров → `basis = none`
   (строка пишется); свои с `own_sync/x_api` и ≥ 20 своих постов формата за 90 дней →
   перцентиль `(ниже + ½·равных)/n` с границами 0.10/0.35/0.65/0.90; иначе доли. Пост моложе
   24 ч → строки нет, задача `brain.outcome` на `posted_at + 24 ч` (идемпотентно). Новая строка
   исхода — только если изменились basis/источник/доли/ступени (в таблице нет `signal_id`).
7. **Импорт истории** (`brain/history.py`): `XClient.iter_own_history`; материал `own /
   history_backfill`, `status = parsed` (текст есть, в ингест/чанки не идёт — см. «Открыто»),
   сигнал `own_sync`, задача `brain.analyze`; повтор пропускает по `external_id`. Бюджет:
   `check("x_api", $0.001)` до чтения; `BudgetExceeded` посреди — прочитанное остаётся. Исходы
   считаются после чтения всей истории. Итоговый текст (Soft) строится по признакам кода
   лучших и худших 10% по просмотрам — до разбора моделью.
8. **Связка с ингестом — подписчик `emit`** (`brain/jobs.install_analysis_on_ingest`): событие
   `source.ingested` ставит `brain.analyze` в той же транзакции. Ингест не менялся.
   Обработчики: `handle_brain_analyze/outcome/history_import`; воркера в main ещё нет —
   подключить вместе с ним (как `x.recheck_metrics`).
9. **Карточка** (раздел 5.2): `brain/card.render_card`, кнопки `mo:<id>:hit|normal|flop|nums`,
   `ms:<id>:own|anti_example`, `irm:<id>` (из learn). Исход по точным цифрам известен — вопроса
   «как зашёл» нет. Своя история карточек не получает. Строка «совпало со знаниями» — с 9A.
10. **События** (в конец `metrics/events.py`): `material.outcome_computed`,
    `taxonomy.term_proposed`, `taxonomy.term_accepted`, `history.imported`.

## Открыто
- Промпт `brain.read_screenshot.v1` не заведён: чтение скриншота делает `ingest.screenshot`
  (7Δ) по той же схеме `ScreenshotRead`; переименовать — отдельной правкой, если нужно.
- Своя история не режется на чанки и не попадает в паспорт/ретривал — решить вместе с
  синком этапа 14 (сейчас голос берётся из присланных своих постов).
- Повторная проверка `meta.screen = 'unavailable'` (заметка 7Δ) не сделана — такие материалы
  просто ждут.
- Критерий «100 материалов за 10 минут и < $0.15» проверен на подделках (цены пика DeepSeek,
  2 000 вход + 550 выход без скидки кэша ≈ $0.126); вживую и eval (40 постов) — с ключом.
