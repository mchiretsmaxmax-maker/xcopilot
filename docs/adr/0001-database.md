# ADR-0001: PostgreSQL 18 + pgvector как единственное хранилище

Статус: принято (этап 1).

## Контекст
Нужны транзакции, партиции событий, полнотекстовый и триграммный поиск, векторный поиск по текстам аккаунта, очередь задач и метрики. Команда одна, сервисов должно быть минимум.

## Решение
Одна БД PostgreSQL 18 (образ `pgvector/pgvector:pg18`) с расширениями pgvector и pg_trgm. Доступ — SQLAlchemy 2 (async) + asyncpg, миграции — Alembic. Очередь задач и метрики живут в той же БД. Порт БД наружу не публикуется: она доступна только сервису `app` внутри сети compose.

## Последствия
- Нет отдельных Redis, брокера и векторной БД: проще деплой и бэкап.
- Масштаб ограничен одной БД; для одного владельца и нескольких аккаунтов этого достаточно.
- Тесты integration идут на настоящем PostgreSQL (testcontainers), а не на SQLite.
