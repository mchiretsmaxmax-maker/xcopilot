# ADR 0036 — Параллельные ворота и ограничение ожидания

Принято 23.11.2026 по запросу владельца.

Задача `quality.gate` проверяет до трёх разных черновиков одновременно. Ответы возвращаются в порядке исходного payload. При ошибке одной проверки или отмене задачи остальные проверки отменяются, обработчик дожидается их завершения. Повторяющийся ID проверяется один раз.

Вызовы Codex для `writer.generate`, `writer.topics`, `writer.trend_tail` и `draft.rewrite` ограничены 45 секундами на попытку, включая ожидание свободного процесса. Допускается один повтор временного сбоя. Исчерпавший обе попытки тайм-аут завершает пользовательскую задачу с сообщением владельцу. Повтор всей задачи очередью при таком исходе отключён.

Полный обработчик `writer.generate`, `writer.topics` и `quality.gate` имеет предел 120 секунд. Превышение времени отменяет дочерние операции и завершает задачу с ошибкой без повторной постановки. Отменённая генерация помечается в `generation_runs` как `failed/interrupted`. Штатная отмена владельцем и завершение процесса сохраняют существующую семантику очереди.

Параллельность Codex по умолчанию повышена до трёх процессов, чтобы переписывания разных вариантов могли выполняться одновременно. Переопределение — `CODEX_CLI_CONCURRENCY`. Модель и усилие остаются в действующих настройках. Для фоновых вызовов применяется прежний профиль ожидания.

Лимит времени задаёт время ожидания обработки. Он не гарантирует успешной генерации за этот срок. Сообщения вариантов показываются существующим способом после окончания ворот.
