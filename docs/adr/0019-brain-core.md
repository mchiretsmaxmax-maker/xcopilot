# ADR-0019: «Мозг-ядро» — знания из разборов, веса, переходы, откат

Статус: принято (этап 9A, ветка `stage/09a-brain-core`, 15.11.2026).
Источник: ТЗ v3.1, этап 9A; `docs/brain-v3.1.md`, разделы 1.2, 1.4, 2.4–2.6, 3.1–3.3, приложения D, E.

## Что сделано
1. **Пакет `xcopilot.brain` (9A).** `detectors`, `evidence`, `extract`, `sanitize`, `merge`,
   `compat`, `scoring`, `lifecycle`, `snapshots`, `rollback`, `seed`, `jobs`, плюс `config`
   (`config/brain.toml`), `context` (`BrainContext`), `judge_questions` (вопросы приложения E).
   Все операции принимают `BrainContext` (сессия, аккаунт, часы, модели, эмбеддер, настройки):
   сигнатуры ТЗ (`record_from_material(source_id)` и т. п.) получили первым аргументом `ctx`.
2. **БД только через `db/repos/brain.py`** (`BrainRepo`) — слой `brain` не содержит SQL
   (`test_layering`). Разборы читаются из `material_analyses` напрямую; функции 7A не
   импортируются (договорённость 7A/9A).
3. **Миграция `0007_knowledge_priors`.** Колонки `eff_prior_alpha/beta`, `fit_prior_alpha/beta`
   в `knowledge_items` (по умолчанию 1/1 и 2/1, CHECK > 0); `knowledge_recompute_scores` берёт
   априор из них. Нужно для копий общего шаблона «с априором, ослабленным вдвое» (раздел 8.3):
   раньше функция держала априор в теле и затирала его при каждом пересчёте. Downgrade
   возвращает функцию 0004 дословно.
4. **Детекторы.** `feature` — код по `ALLOWED_PATHS`; отсутствующее поле — условие не выполнено.
   `rubric` — судья, вопросы пачками по 10, на материал не больше 30 знаний, ближайших по вектору
   к тексту (знания без вектора — следом, по качеству). Текст — `wrap_untrusted`. ≥ 0.7 — есть,
   ≤ 0.3 — нет, между — не учитывается.
5. **Доказательства.** Множители раздела 2.4 из `brain.toml`; свой пост — `own_outcome`,
   `w_source` 1.0, `w_scope` 2.0, без скидки; статья с заявленными утверждениями — `declared`, 0.3;
   `owner_pick` — 0.25; неизвестный исход — строки нет; `w_author = 1/k`. `created_at` ставится
   часами приложения (пересчёт «на дату» идёт по нему). Знание слоя voice чужие материалы
   пропускает (и триггер БД это держит). Решения по черновикам: approve без правок +1.0,
   правка с дистанцией ≥ 0.5 −0.5, отказ с `reason_code` `not_my_voice`/`sounds_ai` −1.5 —
   **коды причин должен использовать этап 12** (`brain.evidence.VOICE_REJECT_CODES`).
6. **Извлечение.** Пачка формата — когда накопилось 10 новых разборов или самый старый ждёт
   сутки; до 25 в пачке. Своя история (`origin = history_backfill`) — контрастная выборка 20%
   сверху и снизу по `pct_engagement` (нет — по ступени исхода); середина отмечается обработанной.
   Модели уходят разборы без дословных цитат (ключи, признаки, гипотезы без цитат, число маркеров);
   блок материалов обёрнут как недоверенный. Обработанная пачка — событие
   **`brain.extraction_done`** (новое, в конце `EventType`): повторный прогон её не берёт.
7. **Приём кандидата.** ≥ 2 материала «за» (для voice — только свои, ≥ 2); `same_as_existing` —
   доказательства к существующему, нового знания нет; судья: `is_craft_claim` < 0.7 и
   `portable` < 0.5 (не voice) — отказ, слой судьи с уверенностью ≥ 0.7 заменяет слой;
   совместимость с паспортом (`allowed × natural / 2`; без паспорта — 1.0) пишется в
   `provenance.voice_compat` версии. Класс риска по слою: voice → A, humanness → C, иначе B.
8. **Слияние.** До 5 ближайших выше `embedding_models.related_threshold`; «то же» ≥ 0.7 —
   кандидат → `merged` в старшее, доказательства копируются старшему (у младшего отзываются с
   причиной `merged`), связь `duplicates`; «уже/шире» — `refines`/`generalizes`; «противоречит»
   ≥ 0.6 — открытая связь `contradicts`, обе стороны → `conflicted` (переход `conflict_opened`).
   Авторазбор: разрыв (own_support − own_contra) ≥ 3 — победителю отменяется переход в conflicted,
   проигравший → `archived` (`conflict_resolved`).
9. **Переходы.** `lifecycle.RULES` — таблица раздела 2.4; `evaluate` — чистая функция над
   `ItemState`. Лимит автоиспытаний — переходы `auto_probation` за 7 суток без `reverted_at`.
   Pinned не ослабляется и не архивируется; класс A автоматически не повышается. В `payload`
   перехода — все числа и пороги. События: `knowledge.transition`, `knowledge.reverted`
   (actor события — `user`/`system`; в props — `owner`/`system`, как в схеме событий).
10. **Откат без своей таблицы.** id отката (uuid) — в причине отзыва доказательств
    `rollback:<id>`, в `payload.rollback_id` переходов (rule `rollback`) и в
    `provenance.rollback_id` версий текста; событие `knowledge.rollback` — `entity =
    ("knowledge_rollback", id)`. Статус возвращается к `from_status` первого перехода после T
    (точнее снимка внутри дня), решение владельца — из снимка на дату T. Отмена: снять отзыв,
    откатить переходы отката, вернуть текст версией, бывшей до отката.
11. **Сид.** Анти-AI правила этапа 8 → global как `anti_pattern / humanness / C / active / seed`,
    ключ правила в `provenance.seed_key` (повтор — 0). Копия в аккаунт: `parent_item_id`,
    априоры × 0.5 (`[seed] prior_factor`). Вызов `copy_seed_to_account` при онбординге и
    `load_global_seed` при старте — **подключить при сборке процесса** (воркера ещё нет).
12. **Снимок дня** снимается один раз (повтор того же дня — 0). Ночная задача: пересчёт со спадом,
    переходы, авторазбор конфликтов, снимок по поясу аккаунта.
