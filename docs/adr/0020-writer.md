# ADR 0020 — Писатель (этап 10)

Статус: принято (15.11.2026).

## Решения

1. **Модули.** `writer/schemas.py` (TopicIdea, TopicsOut, DraftOut, DraftBatch, WhyItWorked, Topic, TargetPost, DraftView, GenerationRun), `formats.py`, `similarity.py`, `topics.py` (`TopicService`), `drafts.py` (`WriterService.generate/generate_tail`), `trend_tail.py`, `render.py` (разделы промпта), `knowledge.py` (`PackRecorder`), `probation.py` (`ProbationPicker`), `jobs.py` (задачи очереди). Запросы — `db/repos/writer.py` (`WriterRepo`) и `RunsRepo.by_job`; SQL и модели вне `xcopilot.db` не появляются (тест слоёв).
2. **Пакет — этап 9.** `build_pack` даёт паспорт, примеры, знания (`KnowledgeProvider`, по умолчанию `NoKnowledge`), факты, антипримеры; писатель только раскладывает секции по промпту.
3. **Промпты.** `writer.draft.v1`, `writer.trend_tail.write.v1`, `writer.topics.v1` (роль writer). Кэшируемые блоки: системные инструкции и `<passport>` (паспорт + «# Жёсткие правила»); всё, что зависит от задачи (тема, знания, примеры, факты, чужой пост), — в пользовательской части. Порядок важности в инструкции: жёсткие правила → паспорт → «## Знания под задачу» (формат brain 4.3, фраза «Жёсткие правила паспорта важнее…», без цифр уверенности). Политика цифр: цифры/имена — только из «Факты», нет фактов — нет цифр, цифры чужого поста — не факт. Чужой текст (целевой пост, оригинал тренда) — `wrap_untrusted`; свои посты в промпте черновика не оборачиваются (это свой голос). Промпт `writer.trend_tail.analyze.v1` **не создаётся**: v3.1 заменил разбор чтением `material_analyses`.
4. **Вызовы писателя.** Без испытуемого знания — один вызов на n вариантов (`DraftBatch`). С ним — вызов на n−1 обычных и отдельный вызов на вариант 🧪 (раздел «### Испытание — только для этого варианта»): так испытуемое знание гарантированно не попадает в промпт обычных вариантов. Испытуемое знание исключается из знаний пакета. `TaskSpec.include_probation=false` выключает 🧪.
5. **Различие.** Варианты: rapidfuzz (max(ratio, token_sort_ratio) после нормализации) ≥ 0.8 — из пары перегенерируется поздний, одна перегенерация (обычные — одним вызовом, 🧪 — своим); осталось похоже — предупреждение `variants_similar`. Хвост тренда: сходство с оригиналом ≥ 0.6 — одна перегенерация, затем вариант отбрасывается (`near_copy_dropped`). Темы — косинус эмбеддинга заголовка > 0.85 к темам за 30 дней (по `clock`, `topics.created_at` пишется явно) и к уже взятым в ответе. Лексика — rapidfuzz, смысл — эмбеддинги.
6. **Запись пакета знаний — писателем, за интерфейсом.** Пока провайдер отдаёт только список, строку `knowledge_packs` (consumer=writer, items `[{item_id, version, slot, rank, score}]`) пишет `DbPackRecorder` и шлёт `knowledge.pack_built`, если есть знания или 🧪. Этап 9B подменит `PackRecorder` (параметр `WriterService(pack_recorder=…)`).
7. **`knowledge_applications`.** На каждый вариант × каждое знание пакета: slot `pinned`/`anti`/`core` по слоту знания; испытуемое — `probation` только у своего варианта. `applied` не заполняется (этап 13/9B).
8. **`generation_runs`.** `passport_version`, `prompt_id` (версия промпта по хэшу из реестра; нужен `PromptRegistry.sync` при старте), `knowledge_pack_id`, `context_pack` = `PackIds` + `job_id`, `hint`, `probation{item_id,guidance}`, `target_url`, `trend{source_id,url,analysis_id,own_topic}`. Статусы: `running` → `done` | `failed` (`budget_exceeded`, `writer_unavailable`, `writer_error`, `no_variants`).
9. **Идемпотентность.** Задача очереди передаёт `job_id`; готовый запуск этой задачи возвращается как есть (`reused=True`, карточки повторно не шлются); незавершённый переиспользуется. Черновики, применения знаний и завершение запуска — одна транзакция, поэтому частичных наборов нет.
10. **Очередь.** Виды `writer.generate` (payload `mode: draft|trend_tail`) и `writer.topics`. **Воркера в проекте нет**: обработчики (`handle_writer_generate`, `handle_writer_topics`) тестируются напрямую, `process_writer_job(queue, job, handler)` — то, что воркер сделает: успех → `complete`; модель-автор недоступна (`ProviderUnavailable`) → уведомление владельцу на первой попытке + `fail` (повтор с паузой), других моделей нет; бюджет исчерпан / неверная задача / поста нет → `complete` без повтора.
11. **Форматы.** Пост ≤ 280, длинный — если `hard_rules.max_len > 280` (до этого потолка); тред 3–8 частей по 280 (части без `parts` режутся `split_thread`); ответ и цитата ≤ 280 и только с целевым постом (без него `WriterInputError` до модели). Нарушения формата пишутся в `drafts.lint_report.format` — ворота качества (этап 11) расширят отчёт.
12. **Хвост тренда.** Пост — по `source_id`, по ссылке среди источников аккаунта или текстом. Разбор — текущая строка `material_analyses` (WhyItWorked, `label="гипотеза"`); нет строки — «разбора нет», без вызова модели. Функции 7A не импортируются.
13. **События.** Новое: `run.finished {kind, status, drafts, reason}` (в конце `metrics/events.py`). Используются `run.started`, `draft.generated`, `topic.suggested` (origin suggested/manual), `knowledge.pack_built`, `retrieval.pack_built`, `user.action` (`menu.write/topics/trend`, `write.format.*`, `write.target`, `write.topic`, `write.pick_topic`, `topics.write`, `topics.drop`, `trend.post`).
14. **Бот.** Роутеры `write`, `topics`, `trend` — раньше `menu`. Кнопки: `wfmt:<fmt>`, `wpick:<topic>`, `wtopic:<topic>:<fmt>`, `wdrop:<topic>`. Карточки вариантов — простые сообщения («Вариант i/n», части треда, «🧪 Проверяю приём: …»); кнопки карточек — этап 12.
