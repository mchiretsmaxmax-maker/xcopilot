# ADR 0033 — Автоисход по публичным цифрам и одна сводка на пачку

Статус: принято (18.11.2026). Ветка `feat/auto-outcome`. Миграция `0012_public_metrics`.

## Проблема

Владелец прислал 20 ссылок — бот прислал 20 карточек «🧩 Разбор» и по каждой спросил «Как он зашёл?». Ключей X API нет, но публичные цифры поста отдаёт fxtwitter (проверено на реальном ответе `api.fxtwitter.com`: `likes`, `retweets`, `replies`, `quotes`, `bookmarks`, `views` — у старых постов `null`, `author.followers`). Решение владельца: исход ставить автоматически по этим цифрам, на пачку — одна сводка.

## Решение

1. **Цифры при чтении.** `PublicPostReader`: если oEmbed дал полный текст, идёт ещё один запрос к fxtwitter только за цифрами (текст остаётся от oEmbed; сбой fxtwitter — пост без цифр). `parse_fxtwitter` берёт также `bookmarks`, `views` (→ `XMetrics.impressions`) и `author.followers` (→ `XPost.author_followers`). Наружу по-прежнему уходит только адрес публичного поста.
2. **Хранение.** Ингест пишет наблюдение `material_signals` с новым `origin = 'public_metrics'` (просмотры, лайки, ответы, ретвиты, цитаты, закладки, подписчики, возраст поста; `raw.via`). Отдельного поля в `sources` не нужно: таблица сигналов и есть место для цифр материала.
3. **Миграция 0012** (без неё нельзя): `public_metrics` в CHECK `origin`; в `v_material_best_signal` он стоит **после `owner_label`**: кнопка владельца перекрывает автоисход, а точные цифры (свои посты, X API, скрин, ввод цифрами) — и то и другое. Даунгрейд удаляет такие сигналы.
4. **Автоисход** (`brain/outcomes.py`, тот же `compute_outcome`): оценка `(лайки + 2·ответы + 3·ретвиты) / просмотры`, если просмотров нет — `/ подписчики автора`. Ступень одна на все цели (hit / normal / flop), `basis = rates`, `signal_origin = public_metrics` — так авто отличается от ручного. Нет ни просмотров, ни подписчиков → исхода нет. Посту меньше `defer.hours` (24 ч) → исхода нет и отложенной задачи тоже нет: перечитать цифры через сутки пока некому, ранние цифры занижают исход.
5. **Пороги** — `config/outcomes.toml [auto]`:
   - `by_views = [0.005, 0.03]`: у X типичная вовлечённость 0.5–1% от просмотров; взвешенная оценка (ответ ×2, ретвит ×3) у обычного поста 1–2%. Меньше 0.5% — заметно ниже нормы, 3% и выше — пост явно разошёлся.
   - `by_followers = [0.002, 0.02]`: просмотры обычно в разы больше лайков, а подписчиков видит пост только часть; 0.2% аудитории — вялый отклик, 2% — сильный.
   Это допущения до накопления данных, как и остальные пороги `outcomes.toml` (этап 20 заменит их квантилями).
6. **Вес.** `reliability.public_metrics = 0.3` и `weights.source.public_metrics = 0.3` — ниже `owner_label` (0.4). Свои посты (`stance = own`) тоже получают автоисход и идут в доказательства как `own_outcome` (вес 2.0 за близость).
7. **Исход доходит до весов.** Раньше смена исхода после разбора (кнопка владельца) не меняла доказательства: `insert_evidence` пропускает повтор. Теперь `_store` при замене текущего исхода ставит `brain.detect` с `revise: true`; `evidence.revise_material` отзывает доказательства материала (`outcome_revised`), записывает их заново по текущему исходу и пересчитывает веса.
8. **Одна сводка на пачку** (`brain/batch.py`). Пачка — `sources.meta.batch`. Материал из пачки >1 после разбора карточку не шлёт. Когда все материалы пачки разобраны (или упали/исключены/убраны) — одно сообщение: счётчики 🔥/👍/👎/❔ (и «⏳ N свежие, оценю позже» — посты моложе суток, у которых цифры есть, но исход ещё не ставится), три частых хука и приёма, кнопки `mbs:<пачка>:show:<с какого>` (карточки по 5; с исходом — без вопроса), `:own` / `:inspiration` (отношение всей пачки + `brain.detect revise` по каждому), `:rate` (материалы без исхода по одному; после оценки — следующий). Флаг `meta.analysis_summary_sent` защищает от двойной отправки. Задача `brain.batch_summary` через 10 минут после первого разбора шлёт сводку по готовому с «ещё разбираю N»; опоздавшие приходят обычными карточками.
9. **Один материал** — карточка как раньше; при автоисходе вместо вопроса строка «Зашёл: 🔥 (1.2k лайков, по цифрам)» и кнопка «✏️ Поправить оценку» (`moe:<id>` → кнопки оценки).

## Последствия

- На каждую ссылку два внешних запроса (oEmbed + fxtwitter). Тест `test_oembed_ok_no_fxtwitter_call` исправлен отдельным `test-fix:`.
- Сводка анализа приходит в дополнение к итогу приёма («Готово: N разобрано… Это что?»); объединить их — отдельная задача.
- Автоисход молодого поста не ставится; повторное чтение цифр через сутки — возможное продолжение.
