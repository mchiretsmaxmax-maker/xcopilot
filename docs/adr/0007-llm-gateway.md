# ADR-0007: LLM-шлюз

Статус: принято (этап 4, 13.11.2026).

## Контекст
Шаги конвейера вызывают модели по роли (writer / judge / cheap), получают проверенный
типизированный ответ, а каждый вызов учтён в журнале и бюджете (ТЗ, этап 4; ADR-0002).

## Решение
- **Один вход** — `xcopilot.llm.gateway.LLMGateway`: `generate(role, prompt_key, variables,
  schema, account_id, purpose, entity)` → pydantic-модель; `decide(state, questions, …)` → `Verdict`.
  Сборка из настроек — `llm.factory.build_gateway(settings, uow_factory, clock)`.
- **Конфиг ролей** — `config/models.toml` (провайдер, модель, max_tokens, `[fallback]`); цены —
  `config/pricing.toml` (USD за 1M, дата сверки `verified`, строка `default` у провайдера, поэтому
  смена модели — одна строка `models.toml`; проверено тестом). Каталог — `$XCOPILOT_CONFIG_DIR`
  или `./config`; в образ копируется `config/`.
- **SDK**: anthropic 2.8, openai 3.50 (DeepSeek, base URL `https://api.deepseek.com`),
  typesafe-sdk 0.7.5 (Jev, `POST /v1/systemone`) — все на PyPI. Все три ходят через `httpx2`,
  поэтому кассеты подставляются `httpx2.MockTransport`, а не respx. Повторы SDK выключены
  (`max_retries=0`): повторы и предохранитель — в шлюзе.
- **Типизированный ответ**: JSON-схема pydantic-модели в запросе; невалидный ответ — одна
  починка (ответ модели + текст ошибки), вторая неудача — `LLMOutputError` и событие `llm.failed`.
- **Судья**: `NoulQ` / `ChoiceQ` (2–255 вариантов) / `ScoreQ` (2–10 уровней) → ответы
  `NoulA(p)`, `ChoiceA`, `ScoreA` с вероятностями. `DecisionProvider.decide` возвращает
  `DecisionResult(answers, usage, model)`, а не голый dict: токены нужны журналу.
- **Замены**: у writer и cheap нет. Judge → cheap с тем же набором вопросов (промпт
  `judge.fallback`, текст обёрнут как недоверенный) и `Verdict.fallback=True`; вероятности
  резерва — выбранному варианту уверенность, остальным поровну. Оба недоступны → `ProviderUnavailable`.
- **Сбои**: временные (408, 409, 429, 5xx/529, таймаут, обрыв) — до 3 повторов, экспонента с
  разбросом ≤ 8 с; прочие 4xx не повторяются. Предохранитель на провайдера: 5 неудач подряд →
  разомкнут 30 с → один пробный вызов.
- **Журнал `llm_calls`**: строка на каждый вызов провайдера (в т.ч. починку и ошибку): токены,
  `cached_tokens` = чтение кэша, цена, задержка (по `Clock`), статус, класс ошибки и код,
  версия промпта, сущность. Миграция **0003** добавила `entity_type` / `entity_id` + индекс
  (для стоимости по черновику); отдельного события `llm.called` нет.
- **Цена**: целые микродоллары, округление вверх. Claude — вход, выход, чтение и запись кэша
  отдельно; DeepSeek — `peak_*` в 01–04 и 06–10 UTC по будням; Jev — только вход. Кэш-скидка
  DeepSeek не учитывается (оценка сверху).
- **Бюджет** (`BudgetGuard`): лимиты из `budgets` (day / month) или дневной по умолчанию из
  настроек; сутки и месяц — в поясе аккаунта; потрачено = сумма журнала (`llm_calls` или
  `x_api_calls`). `check` до вызова: жёсткий → `budget.exceeded` (раз за период) и
  `BudgetExceeded`, провайдер не вызывается; мягкий → `budget.warning`. `record` после записи
  журнала: ≥ 80% → `budget.warning` раз за период. Для x_api `record` не вызывается.
- **Промпты**: `llm/prompts/*.md` с шапкой (key, role, cacheable); `sync(session)` пишет новую
  версию только при новом sha256 файла. Переменные из `cacheable` (паспорт, уроки) — отдельные
  системные блоки с `cache_control` у Anthropic.
- **Секреты**: адаптеры поднимают свои ошибки вне `except` (без `__context__` с телом ответа);
  в журнал и события — только класс ошибки и HTTP-код. Проверено тестом с ключом в теле 401.

## Что осталось / риски
- Кассеты (`tests/fixtures/cassettes/*.json`) собраны по документации, ключей не было.
  **Перезаписать настоящими ответами** при первой live-проверке (`uv run pytest -m live`) и
  сверить: заголовок ключа, `usage` (особенно кэш Anthropic и `prompt_cache_hit_tokens` DeepSeek),
  точное имя модели Jev (закрепить в `models.toml` вместо `jev-latest`).
- Отметка «раз за период» проверяется по `events` без блокировки: при параллельных вызовах
  возможен дубль события — допустимо.
