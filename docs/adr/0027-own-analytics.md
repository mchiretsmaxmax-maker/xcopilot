# ADR 0027 — Своя аналитика (этап 14)

Статус: принято (16.11.2026). Миграции нет (0011 свободна).

## Решения

1. **Модули.** `analytics/sync.py` (`OwnSync`: `sync_own_posts`, `schedule_checkpoints`, `take_snapshot`; `SyncResult`, `SnapshotResult`), `baseline.py` (`baseline`), `patterns.py` (`Period`, `Pattern`, `Patterns`, `compute_patterns`, `to_candidates`), `analyst.py` (`Analyst.build_report`, `Claim`, `AnalystReport`, `render_claims`), `reports.py` (`Reports.daily_report`, `daily_report_template`, `DayStats`), `drift.py` (`drift_alert`), `jobs.py`, `kit.py` (`AnalyticsKit`, `build_analytics`). Запросы — `db/repos/analytics.py` (`AnalyticsRepo`; SQL вне `db` запрещён тестом слоёв). Бот: `bot/routers/stats.py` (`/stats`, `menu:analytics`, кнопки «Что зашло / Что улучшить / Цифры»). Отступление от ТЗ в сигнатурах: функции — методы сервисов, первый аргумент `account_id`; `schedule_checkpoints(account_id, x_post_id, published_at)` вместо объекта публикации.
2. **Синк.** Раз в день (`analytics.sync`, 06:00 по поясу аккаунта). `since_id` = наибольший `external_id` среди своих материалов (история тоже считается, поэтому после импорта посты не читаются заново). Режимы `off` и `lookup` — пропуск без вызова X; `accounts.settings.x_sync_paused` — пропуск; `XAuthError` — пауза + сообщение владельцу. Новый пост: материал `stance=own`, `origin=x_api`, `status=parsed`, `analysis_status=pending`, `content_hash = sha256("x:<id>")` (тот же, что у импорта истории: один пост — один материал), документ, сигнал `own_sync`, первый снимок метрик, задачи `ingest.process` и `brain.analyze`. Стоимость пишет сам `XService` (`x_api_calls`, $0.001 за пост).
3. **«С ботом / без бота».** `sources.meta.bot_assisted` (true/false) проставляется после автосверки по таблице `publications`; пост, который позже сверился, перепомечается в true. Посты без бота учатся так же (доказательства `own_outcome` не зависят от пометки).
4. **Автосверка после синка.** `OwnSync` вызывает `PublicationMatcher.match_publications` с только что прочитанными постами (X второй раз не читается); неоднозначные — вопрос владельцу той же клавиатурой, что у `publications.match`.
5. **Контрольные снимки.** `schedule_checkpoints` ставит `analytics.snapshot` на 1ч/24ч/72ч/7д (`run_at` = публикация + отметка, ключ идемпотентности `analytics.snapshot:<пост>:<минуты>`), вызывается для каждого нового поста моложе 7 дней. Снимок: чтение своего поста (`XClient.get_post`), строка `post_metric_snapshots` (`age_minutes` от времени поста), сигнал `own_sync`. Ограничение: публикации, подтверждённые вне синка (по ссылке), чекпоинты получают при ближайшем синке, а не в момент подтверждения.
6. **Исход и знания на отметке 24 ч (v3.1).** `take_snapshot(…, 1440)`: `outcomes.compute_outcome` (перцентиль среди своих постов формата за 90 дней, если постов ≥ 20, иначе доли от показов), затем `brain.evidence.record_own_outcome` (детекторы на текущем разборе; вес 2.0, без скидки за автора) и `recompute`. Знание, которого нет в тексте, доказательств не получает. Потолок «только чужие исходы» 0.70 снимается первым исходом на своём посте — проверено тестом.
7. **Базовый уровень и закономерности.** `baseline`: медиана показов (последний снимок поста) за 30 дней по формату (`sources.kind`). `compute_patterns`: группы по формату, длине (до 100 / 100–200 / длиннее), часу выхода (пояс аккаунта) и теме (`chunks.tags` `topic:*`); закономерность — группа от 3 постов, медиана которой отличается от общей медианы периода на 20 % и больше. Выборка меньше 10 постов — `small_sample` и предупреждение «Мало данных».
8. **Кандидаты знаний (v3.1).** `to_candidates`: только закономерности с ростом показов (падения остаются в отчёте), не больше 12; формат и длина получают детектор-признак, час и тема — `none`; метки `M<n>` — номера постов в `Patterns.sources`. Приём — существующий `brain.extract.ingest_candidates`; единственное изменение в 9A — необязательный аргумент `origin="materials"` у `ingest_candidates` и `_create` (для `own_metrics`; 13 может использовать для `edits`).
9. **Отчёт аналитика.** Модель роли `writer` (промпт `analyst.report.v1`) получает уже посчитанные строки закономерностей и только пересказывает. Пункт отбрасывается, если у него нет ни одного id поста из расчёта или в тексте есть число, которого нет среди посчитанных (`number_grounding`: `quality.lint.numbers.is_grounded`). «Что улучшить» — не больше трёх. Модель недоступна — отчёт только с цифрами. Недельный отчёт: ежедневная задача по понедельникам добавляет его владельцу.
10. **Ежедневный отчёт.** `reports.daily` (08:00 по поясу аккаунта): вчера по поясу аккаунта — число постов, лучший пост и % к базовому уровню, «без правок одобрено X из Y», расход (`llm_calls` + `x_api_calls`), строка про знания («подтвердил N и опроверг M: …»). Дешёвая модель (`reports.daily.v1`) только пересказывает шаблон; недоступна или в пересказе есть число не из шаблона — уходит шаблон. Режим `off`: охватов нет (посты считаются по `publications`, без показов).
11. **/stats.** Свёртка `metric_values` за 7 дней (суммы для счётчиков, средневзвешенное по `sample_size` для долей и медиан). Режим `off` скрывает охваты и подписчиков; меньше 10 постов — предупреждение.
12. **Метрики и дрейф (v3.1).** `brain_knowledge_lift`, `brain_thesis_precision_own`, `brain_voice_drift` уже в каталоге 9A; этап проверил их на фикстурах (`tests/integration/analytics/test_metrics_v31.py`). Алерт: `drift_alert` сравнивает последнее недельное значение `brain_voice_drift` с первым; рост ≥ 25 % — сообщение владельцу в ежедневной задаче.
13. **Своя история в куски (открытый вопрос 7A).** `HistoryImporter` ставит `ingest.process` для каждого импортированного поста (как и синк): `stance=own` не проходит проверку на входе (`_screen`), статус `parsed → indexed`, появляются куски, теги и векторы — история попадает в паспорт стиля, ретривал и базу метрики дрейфа голоса (она считает центроид по `origin = 'history_backfill'`). Один пост = один куск, платной модели в пути нет (теги — дешёвая модель, как у любого материала). Уже импортированные посты (до этого этапа) куски не получили: `brain.history_import` повторно пропускает их по `external_id`; для них нужен разовый запуск `ingest.process` по `sources WHERE origin = 'history_backfill' AND status = 'parsed'`.
14. **Очередь и сборка.** `KNOWN_KINDS` + `build_registry`: `analytics.sync`, `analytics.snapshot`, `reports.daily`; `JobDeps.analytics`, `BotDeps.analytics` (`AnalyticsKit`) собираются в `app.build_app`. `DEFAULT_SCHEDULES`: `analytics.sync` 06:00, `reports.daily` 08:00. Роутер `stats` подключён перед `menu` (перехватывает `menu:analytics`).

## Не сделано / дальше
- Критерий «три дня подряд без ручного вмешательства, расход на X ≤ $0.50, хотя бы одно знание с исходом на своём посте» проверяется только вживую (нужны токены бота и X).
- Чекпоинты для публикаций, подтверждённых по ссылке, ставятся при ближайшем синке (п. 5).
- Для уже импортированной истории куски не создаются автоматически (п. 13).
- Живой прогон отчётов на настоящих моделях не делался: промпты `analyst.report.v1` и `reports.daily.v1` проверены на подделках.
