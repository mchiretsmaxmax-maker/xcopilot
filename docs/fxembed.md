# FxEmbed (api.fxtwitter.com): что есть и что используем

Проверено 18.11.2026 живыми запросами без ключа (User-Agent `xcopilot/1.0`). Репозиторий: https://github.com/FxEmbed/FxEmbed (MIT, Cloudflare Worker), документация: https://docs.fxembed.com/api/introduction, описание API в машинном виде: `https://api.fxtwitter.com/2/openapi.json`. Лимит API v2: 1000 запросов в минуту с одного IP. Сервис сторонний, без гарантий: при сбое бот работает без этих данных.

## Сейчас в боте

С 18.11 (ветка `feat/fxembed-v2`, ADR 0031 «Дополнение») `src/xcopilot/x/public_read.py` ходит в v2:

| Функция `PublicPostReader` | Метод API | Что даёт |
|---|---|---|
| `get_post(ref)` / `fetch` | `/2/status/{id}` | текст, автор, дата, лайки, репосты, ответы, цитаты, закладки, просмотры, подписчики автора + `lang`, `replying_to`, `media`, `is_note_tweet` |
| `fetch_thread(ref)` | `/2/thread/{id}` | части треда автора по ссылке на любую часть |
| `fetch_target(ref)` | `/2/thread/{id}` | пост с текстом всего треда «1/N …» — для «✍️ Написать → Ответ/Цитата» и «💬 Ответы» (`read_target`) |
| `fetch_replies(post_id, limit=30)` | `/2/conversation/{id}?ranking_mode=likes` + `cursor` | ответы по лайкам, без ответов автора и ответов-картинок |
| `fetch_quotes(post_id, limit=30)` | `/2/status/{id}/quotes` + `cursor` | цитаты, до 5 страниц, сортировка по лайкам у нас |
| — | — | Сбор ответов под постами «💬 Ответы» (`brain/harvest.py`, ADR 0034) зовёт `fetch_replies(limit=100)` и `fetch_quotes(limit=40)` |
| `fetch_profile(handle)` | `/2/profile/{handle}` | `XProfile`; пока нигде не используется |

Пауза 0,1 с между запросами и общий ограничитель — не больше 300 запросов в любые 60 с (ADR 0034, запас под чтение постов, пока идёт сбор ответов); не больше 5 страниц на листание, таймаут 10 с; 429/5xx — `XUnavailable`. Не берём `community_note`, `card`. Кассеты: `tests/fixtures/x/fxembed/`.

## Методы v2 (проверка 18.11)

| Метод | Ответ | Заметка |
|---|---|---|
| `/2/status/{id}` | ✅ | объект в ключе `status` (не `tweet`, как в v1) |
| `/2/thread/{id}` | ✅ | `thread` — список частей (на проверочном посте 5) |
| `/2/conversation/{id}` | ✅ | `status`, `thread`, `replies`, `cursor`; вирусный пост 1585841080431321088 → 35 ответов за запрос; у постов с 0–1 ответом пусто |
| `/2/status/{id}/quotes` | ✅ | `results` + `cursor`; 20 за запрос |
| `/2/status/{id}/reposts` | ✅ | владелец решил: не нужно |
| `/2/profile/{handle}` | ✅ | подписчики, подписки, число постов, описание |
| `/2/profile/{handle}/statuses` | ❌ | `{"code":404,"results":[]}` даже для elonmusk — причину выяснить |
| `/2/search?q=…` | ❌ | 404, пусто |
| `/2/trends` | ❌ | 200, но `trends: []` |

## Проверено 18.11 (живые запросы для кассет)

- **Ответы (`/2/conversation`)**: параметр `ranking_mode=likes|recency`, по умолчанию `likes`. В `likes` ответы идут строго по убыванию лайков и на следующих страницах тоже (XDevelopers: 499 → … → 6 на первой, 6 → … на второй). 35 за запрос. У каждого ответа свои `likes`, `reposts`, `replies`, `views` (у старых постов 2022 года `views` = `null`), `lang`, `replying_to`, `author`.
- В тексте ответа X дописывает «@хэндл» в начале (`raw_text.display_text_range` показывает, где начинается сам текст) — отрезаем. Ответы из одной картинки имеют пустой текст — пропускаем.
- Если пост — начало треда, в `replies` попадают и части треда самого автора (naval: 56 из 93), порядок по лайкам при этом нарушен → убираем ответы автора и сортируем у себя.
- **Листание**: `cursor` — объект `{"bottom": "…"}`; передаётся как `?cursor=<bottom>`; повторов между страницами нет. 30 ответов с текстом обычно дает первая страница.
- **Цитаты**: 20 за запрос, `cursor` `{top, bottom}`, порядок — от новых к старым (не по лайкам) → листаем до 5 страниц и сортируем.
- **Тред (`/2/thread`)**: предки поста (любые авторы) + следующие части того же автора. По ссылке на середину треда naval пришло 34 части, по ссылке на первую часть — только 31 (FxEmbed не всегда догружает хвост). `/2/status` поле `thread` = `null`.
- **Профиль**: работает нестабильно — `NASA`, `jack` → 200, `elonmusk`, `XDevelopers` → 404 «User not found» (у `xdevelopers` то 200, то 404). Причину не искали: профиль пока не используется.

## Запрос владельца (18.11)

1. Подключить в клиент: тред целиком, ответы под постом, цитаты поста, профиль (профиль пока только в клиенте, без использования). Репосты — не нужны.
2. Выяснить, почему лента аккаунта (`/profile/{handle}/statuses`), поиск и тренды пустые: смотреть код FxEmbed (нужен ли вход в X / учётка, ограничение гостевого доступа), можно ли обойти законно (свой экземпляр с учёткой, X API, другой путь).
3. Самообучение на ответах: владелец в «💬 Ответы» кидает пост → бот сам забирает 20–30 самых залайканных ответов (и цитат) под ним → они становятся материалом «вдохновение» формата reply/quote → мозг (brain.detect/extract) извлекает из них приёмы → следующие ответы лучше. Всё автоматически, просто от работы в режиме ответов. Сюда же — учёт выбора владельца из 3 вариантов (обсуждался ранее, план не утверждён).
