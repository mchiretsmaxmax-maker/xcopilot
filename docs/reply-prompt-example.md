9. + nullifiers.
- Account — контейнер кода/состояния (бывает публичный и приватный).
- Note — «единица ценности/сообщения», аналог UTXO-выхода, который потребляется транзакцией.
- Nullifier — отметка «note израсходован», предотвращает double-spend. Узлы поддерживают три базы: accounts / notes / nullifiers. =
- Транзакция берёт один account + набор notes на вход и порождает обновлённый account + новые notes. Такая конструкция даёт высокий параллелизм и естественную приватность.
- Private/Public режимы.
- Private account/note: на цепи хранится только 32-байтовый commitment, детали и вычисления остаются у клиента; потребление private-note требует обмена данными по сайд-каналу.
- Public account/note: все детали ончейн, сайд-канал не нужен.
- Edge-execution / client-side proving. Транзакции исполняются и доказываются у пользователя (вплоть до браузера/WASM), сеть лишь проверяет пруф и обновляет глобальные коммитменты и базы nullifiers.
Состояние сети организовано не как в EVM. Вместо «мутирующих счетов» с общим хранением здесь сочетаются аккаунты и заметки (notes). Аккаунт — контейнер кода и состояния (кошелёк, контракт, стратегия), причём он может быть публичным (всё ончейн) или приватным (ончейн хранится лишь 32-байтный commitment, а фактическое состояние и след вычислений держит владелец). Note — одноразовая «единица ценности/сообщения»: её потребление пожирает вход и выпускает новые выходы. Дабл-спенд предотвращается реестром nullifier’ов — как только note израсходована, соответствующий nullifier фиксируется навсегда. Это даёт сразу два эффекта: естественную параллельность (независимые наборы notes обрабатываются без конфликтов) и чистую приватность (контент приватной note и приватного аккаунта в цепи не виден; ончейн остаются только коммитменты и nullifier’ы). Для передачи приватной note получателю используется сайд-канал (зашифрованный payload вне сети).
