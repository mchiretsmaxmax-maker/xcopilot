# xcopilot — обзор: что есть и как устроено

Состояние на 16.11.2026, `main` на коммите «этап 15a слит». Сверено с кодом; где ТЗ ([architecture-v3.1-plan.md](architecture-v3.1-plan.md)) и код расходятся — написано как в коде и помечено **(≠ ТЗ)**. Статус этапов — [README.md](README.md), решения — [adr/](adr/), эксплуатация — [runbook.md](runbook.md).

xcopilot — Telegram-бот, AI co-pilot для X. Учится голосу аккаунта, копит знания («Мозг»), готовит посты и ответы, проверяет их кодом и судьёй. **Публикует только человек**: бот выдаёт ссылку Web Intent, владелец жмёт «Опубликовать» в X сам ([ADR 0003](adr/0003-publish-via-intent.md)).

## 1. Что бот умеет (глазами владельца в Telegram)

| Раздел | Что происходит |
|---|---|
| **Онбординг** (`/start`) | Ниша → язык → примеры стиля → конкуренты → подтверждение → «что у тебя точно работает» (стартовые правила для «Мозга»). Результат — паспорт стиля. |
| **Приём материалов** («📥 Обучить») | Шлёшь пост-ссылку, текст, скриншот, статью, пересылку, файл. Пачки склеиваются (пауза 8 с). Дубли и недоступное отсеиваются, недоверенный контент идёт через «карантин». Кнопки отношения к автору (свой / образец / чужой) и «Убрать». |
| **Разбор** | Каждый материал размечается дешёвой моделью: тема из таксономии, признаки (кодом), сигналы и исходы, карточка разбора. Своя история постов из X импортируется и попадает в паспорт и поиск. |
| **«Мозг»** (`/brain`) | Знания (правила, приёмы, ошибки) с доказательствами «за/против». Счётчики, сегменты, конфликты, поиск, `/brain add`, `/brain export`, откат на дату `/brain undo` с предпросмотром, недельная сводка с пакетным решением. Новые знания проходят «автоиспытания» (до 5 в неделю), вариант 🧪 в посте — это такое испытание. |
| **Темы и посты** («💡 Темы», «✍️ Написать», «🎯 Хвост тренда») | Форматы: пост, тред (3–8 частей), ответ, цитата. На запрос — **3 варианта**. Каждый идёт через **ворота качества** (линтер → судья → до 2 переписываний; рискованное — к владельцу). Потом карточки: одобрить / править / отклонить / перегенерировать. |
| **Публикация** | Кнопка → Web Intent (или копирование, или тред частями). Бот сам сверяет, что опубликовано: автосверка с лентой (rapidfuzz, раз в день). |
| **Аналитика** (`/stats`, «📊») | Свои посты и метрики на чекпоинтах 1ч/24ч/72ч/7д, базовая линия 30 дней, закономерности → кандидаты в знания, ежедневный отчёт (8:00) и недельный (по понедельникам). |
| **Обучение на правках** | Что ты поменял в черновике перед публикацией, классифицируется; из этого рождаются кандидаты знаний (A — что работает, C — ошибки; C со временем становится правилом линтера). |
| **Прочее** | `/why` (почему такой пост), `/queue`, `/cost` (расход по лимитам), `/settings`, `/health` (только админ: очередь, провайдеры, бэкап), алерты владельцу (задача умерла, 80% лимита, провайдер лежит, бэкап, дрейф голоса). |

### Что не проверено вживую или ждёт ключей

- **Всё писалось на подделках и кассетах.** 1097 тестов зелёные, но живой прогон «тема → публикация» на реальных данных не делался. Бот впервые запущен 16.11 локально.
- **X API**: нет ключей/developer app и баланса. Без них работают oEmbed и режим `lookup` (только присланные посты). Кассеты X синтетические.
- **Писатель**: `claude -p` на подписке (ADR 0011). Внутри Docker-контейнера на сервере `claude login` нет — нужен ключ Anthropic API или CLI в образе (решение 15b).
- **Vision DeepSeek** (скриншоты) вживую не проверен. Eval и `tests/evals/baseline.json` — `status=pending`: нужны 30 настоящих тем и 30 постов владельца.
- **Сервер** (Ubuntu, Docker) и 7 дней работы без вмешательства — это этап **15b**, тег `v1.0.0` ещё не стоит.
- **Фазы 2–3** (этапы 16–21) не начаты.
- В работе параллельно: `fix/bot-ux-progress` (меню, прогресс, `/status`), `fix/long-posts-ru-translation` (длинные посты, перевод). Здесь они не описаны.

## 2. Как работает: процесс и компоненты

```
 Telegram ──long polling──┐
                          ▼
   ┌────────────── один процесс xcopilot/app.py ───────────────┐
   │  ① Бот (aiogram 3)   ② Воркер задач     ③ Планировщик      │
   │   роутеры bot/*       берёт из jobs,      раз в минуту       │
   │   ставит задачи ───►  вызывает обработ-   кладёт в jobs      │
   │                       чики из реестра ◄── плановые задачи    │
   └──────┬──────────────────────┬──────────────────┬───────────┘
          ▼                      ▼                  ▼
     Postgres 18+pgvector   LLM-шлюз (llm/)     X-клиент (x/)
     (всё состояние)        роли+бюджет+журнал  oEmbed / API v2
```

- **Три цикла в одном процессе** (`app.serve_app`): бот, воркер, планировщик. Падает один — останавливаются остальные, процесс завершается кодом 1, Docker Compose его перезапускает. Остановка корректная: текущая задача доделывается до 20 с, иначе возвращается в очередь.
- **Очередь задач — таблица `jobs` в Postgres**, отдельных брокеров нет. Воркер берёт задачу с блокировкой, при ошибке повторяет с паузой до 5 попыток, потом статус `dead` + алерт. Есть ключи идемпотентности (задача не удвоится).
- **Реестр видов задач** (`jobs/handlers.py::KNOWN_KINDS`, 22 вида):
  - ингест и разбор: `ingest.process`, `brain.analyze`, `brain.outcome`, `brain.history_import`;
  - «Мозг»: `brain.detect`, `brain.extract`, `brain.nightly` (03:30), `brain.weekly_digest` (пн 09:00);
  - писатель: `writer.topics`, `writer.generate`, `quality.gate`;
  - публикация и карточки: `cards.expire` (04:00), `publications.match` (04:00, 21:00);
  - аналитика и обучение: `analytics.sync` (06:00), `analytics.snapshot`, `reports.daily` (08:00), `learning.propose` (05:30), `x.recheck_metrics`;
  - служебные: `metrics.rollup` (00:30), `db.ensure_partitions`, `bot.notify_budget`, `ops.alerts` (каждые 15 мин).
- **LLM-шлюз** (`llm/gateway.py`) — единственная дверь к моделям. Вызов идёт по **роли**, не по модели; роль → провайдер/модель в [config/models.toml](../config/models.toml):

  | Роль | Кто | Для чего |
  |---|---|---|
  | `writer` | `claude -p` (Claude Code CLI на подписке, `claude-opus-5-5`) | пишет посты, извлекает знания, переписывает. Замены нет и быть не может |
  | `judge` | DeepSeek (`deepseek-flash`) **(≠ ТЗ: там Jev)** | независимая оценка черновика |
  | `cheap` | DeepSeek (`deepseek-flash`) | разметка, классификация, скриншоты, массовое |

  Вернуть Anthropic API и Jev — правка строк в конфиге ([ADR 0011](adr/0011-subscription-writer.md)). Все промпты — версионируемые файлы (`llm/prompts`), синхронизируются в таблицу `prompts` при старте.
- **Предохранители шлюза**: оценка цены → **бюджет** (`BudgetGuard`: дневные лимиты LLM $5, X $1, X lookup $0.50; превышение = `BudgetExceeded`, провайдер не вызывается) → **автомат отключения** (`CircuitBreaker`, 5 сбоев подряд) → повторы на временных сбоях → строка в `llm_calls` (токены, цена, задержка, версия промпта). Ответ модели проверяется pydantic-схемой: невалидный — одна починка, потом `LLMOutputError`. Чужой текст оборачивается `wrap_untrusted` (данные, не инструкции). Судья недоступен — те же вопросы идут резервной модели (`[fallback]`). Ключи в журнал и ошибки не попадают.
- **X-клиент** (`x/`): один интерфейс, режимы `off` / `lookup` / `owned` / `paid` ([ADR 0004](adr/0004-x-modes.md), [0016](adr/0016-x-lookup.md)): официальный API v2 с OAuth PKCE (токены шифруются Fernet-ключом `SECRETS_KEY`), oEmbed без ключей, подделка `FakeX` в тестах. Каждый вызов учитывается в `x_api_calls` и в бюджете. Intent'ы (`x/intents.py`) — готовая ссылка Web Intent.
- **Эмбеддинги** (`embeddings/`): `fastembed` локально (без платных вызовов), векторы лежат в `pgvector`. Нужны для поиска кусков (ретривал), сопоставления знаний и защиты от дубликатов/копий.

## 3. База данных

PostgreSQL 18 + pgvector, **одна схема на все аккаунты** (каждая строка с `account_id`; репозитории фильтруют по нему автоматически — `TenantRepo`). Миграции Alembic **0001–0010** (`db/migrations/versions/`); номера 0008 нет — осталась как пропуск, 0009 ссылается на 0007 **(так в коде)**.

| Группа | Таблицы |
|---|---|
| Аккаунты и пользователи | `accounts`, `users`, `account_members`, `secrets` (шифрованные токены X), `bot_sessions` (состояние диалогов) |
| Материалы и куски | `authors`, `sources` (вид + отношение `stance`: свой/образец/чужой), `documents`, `chunks`, `embedding_models`, `embeddings`, `competitors` |
| Разборы | `taxonomy_terms` (70 терминов), `material_analyses`, `material_signals`, `material_outcomes`, `facts`, `insights`, `style_passports` |
| Знания и доказательства | `knowledge_items` (+ `_versions`, `_scopes`, `_links`, `_transitions`), `knowledge_evidence`, `knowledge_embeddings`, `knowledge_snapshots` (для отката), `knowledge_packs`, `knowledge_applications`, `segments` |
| Черновики и ревью | `topics`, `generation_runs`, `drafts` (ревизии, отчёт линтера, вердикт судьи), `reviews`, `review_cards` |
| Публикации и метрики | `publications`, `post_metric_snapshots`, `account_metric_snapshots`, `metric_definitions`, `metric_values` |
| События и метрики | `events` (журнал всего значимого), каталог из 28 метрик |
| Задачи | `jobs`, `schedules`, `ops_marks` (отметки бэкапа и алертов) |
| Бюджеты и журналы | `budgets`, `llm_calls`, `x_api_calls`, `prompts` |

- **Партиции по месяцам**: `events`, `post_metric_snapshots`, `llm_calls`, `x_api_calls` (+ `knowledge_snapshots`). Строки вне заготовленных месяцев падают в `*_default`; задача `db.ensure_partitions` создаёт месяцы на 2 вперёд, а алерт срабатывает, если в `DEFAULT` что-то попало.
- **Представления (views)**: `v_post_checkpoints`, `v_draft_funnel` (аналитика постов); `v_knowledge_usable`, `v_knowledge_cards`, `v_segment_items`, `v_knowledge_evidence_summary`, `v_material_best_signal` («Мозг»). В БД также триггер «свой голос» и функция пересчёта весов знаний.
- **Как код работает с БД**: SQLAlchemy 2 async + asyncpg. Слои строгие:
  - `db/models/*` — описание таблиц;
  - `db/repos/*` (около 35 репозиториев: `SourcesRepo`, `DraftsRepo`, `KnowledgeRepo`…) — **единственное место, где пишется SQL**; вне пакета `db` импортировать sqlalchemy нельзя (проверяется тестами);
  - `UnitOfWork` — «одна транзакция на блок»: `async with uow_factory() as uow:` — коммит при успехе, откат при исключении; репозитории создаются поверх `uow.session`;
  - **события**: значимые шаги пишутся в `events` через `metrics.events.emit` (`review.approved`, `source.ingested`, `llm.failed`…); на события подписаны хуки (например, `source.ingested` → `brain.analyze`), из них же считаются метрики.

## 4. Путь одного поста

```
Владелец: «✍️ Написать» → формат → тема
  1. bot/routers/write.py      FSM WriteFlow, собирает TaskSpec, ставит задачу writer.generate
  2. jobs/worker.py            берёт задачу; handler → writer/jobs.py
  3. writer/drafts.py          WriterService.generate:
       ├ retrieval/context_pack  пакет контекста: паспорт стиля + похожие свои куски (pgvector)
       ├ brain/api.build_pack    пакет знаний, отранжированных под задачу (+ вариант 🧪 из автоиспытаний)
       ├ llm gateway, роль writer  (claude -p) → 3 варианта, JSON по схеме
       ├ writer/similarity       защита от копий своих/чужих постов
       └ db: generation_runs + drafts; пакет записывается (knowledge_applications)
  4. quality/loop.py (задача quality.gate), для каждого варианта:
       ├ quality/lint/*          код: формат, запрещённые фразы, ошибки класса C, длина, ссылки
       ├ quality/judge.py        судья (роль judge): голос, «запах ИИ», по теме, обоснованность, риск
       ├ quality/policy.py       пороги config/thresholds.toml → ok / rewrite / needs_owner
       └ rewrite (роль writer) до 2 раз; не вышло или risky → «нужен владелец»
  5. review/presenter.py       карточки HTML в Telegram после ворот (лимит показа, срок 48 ч)
  6. bot/routers/cards.py + review/decisions.py
       approve / edit / reject / regenerate → события review.*, доказательства «fit» для знаний
  7. review/publish.py         Web Intent (x/intents.py) / копирование / тред частями.
                               Бот ничего не публикует сам: подтверждение привязано к версии текста
  8. Владелец жмёт «Опубликовать» в X сам
  9. review/matcher.py (задача publications.match)  ищет пост в ленте, привязывает к черновику
 10. analytics/*               чекпоинты метрик → исход → знания «Мозга» (запись в knowledge_evidence)
 11. learning/*                diff «черновик → опубликованное» → кандидаты знаний A/C
```

Петля замыкается: опубликованное и его результаты возвращаются в «Мозг», и следующий пакет знаний уже учитывает их.

## 5. Где что лежит (`src/xcopilot/*`)

| Папка | Что внутри |
|---|---|
| `app.py`, `main.py` | сборка приложения (`build_app`) и запуск трёх циклов; `config.py` — настройки из `.env`; `clock.py`, `errors.py`, `logging.py`, `healthcheck.py` |
| `bot/` | Telegram: `routers/*` (по разделам: start, onboarding, material, write, topics, trend, cards, queue, brain, stats, style, settings, x_connect, why, cost, health, help), `middlewares/` (доступ, антифлуд, дедуп, ошибки), `keyboards`, `texts`, `states` (FSM), `notify` |
| `jobs/` | очередь `JobQueue`, воркер, планировщик, реестр обработчиков |
| `llm/` | шлюз, роли, бюджет, автомат отключения, провайдеры (`claude_cli`, `anthropic`, `deepseek`, `jev`), промпты |
| `x/` | клиент X (API v2, oEmbed, OAuth), Intent'ы, учёт стоимости |
| `embeddings/` | эмбеддер (fastembed) и его интерфейс |
| `ingest/` | приём и разбор материалов: парсеры (текст, скриншот, статья, пересылка), чистка, дедуп, кусочки, карантин, теги |
| `style/` | паспорт стиля: извлечение, статистика, правила, готовый сид |
| `retrieval/` | поиск кусков и сборка пакета контекста под задачу |
| `brain/` | «Мозг»: разбор материалов, знания, доказательства, детекторы, слияние, веса и переходы, автоиспытания, откат, экспорт, пакет знаний (`api`) |
| `writer/` | темы, генерация 3 вариантов, форматы, защита от копий, хвост тренда |
| `quality/` | ворота качества: линтер (`lint/`), судья, политика, цикл переписывания |
| `review/` | карточки, решения владельца, публикация, автосверка с лентой |
| `learning/` | обучение на правках: diff, кандидаты знаний, синхронизация с паспортом |
| `analytics/` | синк своих постов, чекпоинты, базовая линия, закономерности, отчёты, дрейф голоса |
| `metrics/` | события (`emit`), каталог метрик, ежедневная свёртка |
| `ops/` | `/health`, алерты, админ-команды (`python -m xcopilot.ops.admin`) |
| `security/` | шифрование секретов (Fernet) |
| `db/` | модели, репозитории, `UnitOfWork`, миграции, партиции |

Рядом с кодом: `config/*.toml` (модели, цены, пороги, таксономия, запрещённые фразы, исходы, «Мозг»), `scripts/` (backup, restore, smoke, ds.py, slot.sh), `compose.yaml` и `compose.prod.yaml`, `tests/` (unit, integration, e2e, contract, eval, live).

## Расхождения ТЗ и кода, которые стоит знать

- Судья — DeepSeek, а не Jev; писатель — подписка `claude -p`, а не Anthropic API (ADR 0011).
- Миграции идут 0007 → 0009 (0008 нет).
- Скриншоты читает `cheap` (DeepSeek vision); у `claude_cli` картинок нет.
- Автоматического постинга в X нет и по дизайну не будет.
